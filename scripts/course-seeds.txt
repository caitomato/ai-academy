# 1|AI 基本概念|认识 AI 能做什么，也知道什么时候需要核实。
AI 学习路线概述|4–6|学习 AI 可以从使用工具开始，再用小项目理解原理。把学习拆成概念、工具、作品、编程、原理五个阶段，每个阶段都留下一份可以检查的成果。|想整理读书笔记：先学习如何描述需求，再让工具生成提纲，检查后整理成自己的笔记；遇到自动化需求时再学习编程。|必须先读懂所有数学公式，才能开始使用 AI。|写出一个本周想完成的小作品，以及判断它完成的两个标准。|概念,工具,作品,原理|选一个小目标>用工具做出样例>检查结果并记录问题>带着问题补学原理
大模型|6–10|大语言模型用训练得到的参数，根据上下文计算下一个 Token 的概率。Token 是文字切分后的单位，不一定等于一个汉字或一个单词。文本模型处理文字；多模态模型还可能支持图片或声音，具体能力要看产品。云端模型在服务商机器上计算，本地模型在自己的设备上计算。|输入“今天我准备学习”，模型可能接“编程”也可能接“绘画”。它逐步生成后续内容，并非从一个固定答案列表里检索整篇回复。|模型能生成流畅的文字，就说明每句话都经过事实核查。|把“我喜欢学习 AI”手动分成几块，说明这只是分词示意；再写出云端和本地部署各一个取舍。|Token,参数,文本模型,多模态,云端,本地|提供上下文>计算下一单位的概率>选择一个 Token>追加并继续生成
大模型的局限性|10–13|模型可能编造看似可信的内容，这称为幻觉。训练资料有时间边界，上下文也有长度限制。长期记忆、定时执行和操作文件通常需要外部系统支持，不能只靠模型生成文字。|AI 给出一篇论文的题目和作者。你检索原始发表记录发现不存在，因此把这条引用移除，而不是因为格式像论文就采用。|回答语气越肯定，信息就越可靠。|列出一条必须查证的回答，写下准备查哪个原始来源，以及找不到证据时如何处理。|幻觉,上下文窗口,知识时效,外部工具|识别需要核实的事实>找到原始来源>对照关键细节>标记未证实内容
聊天机器人|13–17|聊天界面负责接收输入、组织对话历史并调用模型。模型本身不一定保存你的长期信息。常见上下文管理方式有保留近期消息、压缩摘要、检索旧记录和持久化偏好，各自会丢失或保留不同细节。|你先说“我每天有 20 分钟”，再问“给我计划”。应用把前文一起提供给模型，模型才可能据此安排短任务。开新会话后需要重新说明，除非产品提供记忆。|换一个聊天窗口，模型一定能记住上个窗口的所有内容。|写一段能独立使用的开场说明，包含学习目标、已有基础和每天可用时间。|对话历史,摘要,检索,持久化|输入新消息>应用整理历史>模型生成回答>应用保存本轮记录
智能体——给大模型装上手脚|17–20|智能体把模型、工具和执行循环连接起来。模型提出行动，程序检查参数和权限后执行工具，再把真实结果交回模型。它像一个带工具箱的助手，但能做什么取决于实际授权和工具能力。|整理虚构商店 ACME 的库存：用户提出目标，模型选择读取表格，工具返回库存，模型算出缺货项，生成草稿，负责人确认后才发送。|模型只要说“已发送”，就足以证明邮件真的发出。|画出整理三条待办事项的流程，并圈出实际写入文件和需要人工确认的位置。|Agent,工具,观察,权限|理解目标>请求工具>执行并返回结果>检查结果或继续行动
提示词技巧|20–24|一条可执行的提示词通常说明目标、背景、输入资料、输出格式和约束。角色可以帮助限定语气，但不能代替事实资料。先给一个简单例子，再写验收标准，比不断堆砌形容词更容易检查结果。|把“帮我学习”改为“我没有编程基础，每天 20 分钟。请把变量概念拆成三步，每步给一个生活例子，最后给一道题；先不要显示答案”。|只要加上“你是世界顶级专家”，就不需要提供具体任务和资料。|为自己的小作品写一条提示词，明确输入、输出和两个验收标准。|目标,背景,样本,输出格式,约束|写明目标>提供必要资料>约定格式与约束>对照标准检查回答
接入大模型|24–26|API 是程序调用服务的接口，API Key 类似可计费的访问凭证。调用时通常需要接口地址、模型标识和认证信息。第三方聚合服务可能转发请求，需了解数据流向与费用；官方和聚合服务的能力并不总相同。|本课程用纸面模拟：应用发送“解释变量”，服务返回文本。真实产品应把密钥放在受控服务端；这个静态学习网站不保存或调用任何密钥。|把 API Key 写进公开网页代码，可以靠隐藏按钮保护它。|画出浏览器、自己的服务端和模型服务三者的关系，并标注密钥应保留的位置。|API,API Key,接口地址,模型标识|确认服务接口>在受控环境配置凭证>发送最小测试请求>检查响应与用量
# 2|常用工具|建立自己的工作台，理解文件、终端和版本控制。
检查已有工具与工作区|27–30（主题改编）|使用已准备好的智能体时，先确认工作目录、可读写范围与输出位置。不同项目的运行环境与依赖需要分别核对；打开工具不等于项目已经具备全部运行条件。|在一个空练习目录中放入三行虚构笔记，让已有助手只读这份文件并报告路径与内容；不修改其他文件。|打开了智能体，就说明它已经能读取电脑上所有项目并运行任何文件。|用清单记录已有工具、练习目录、输入文件、允许动作与验收方式；没有工具时先完成纸面方案。|工作目录,运行环境,权限,依赖|选择已准备好的工具>确认独立练习目录>限定读取范围>核对文件内容与路径
终端工具|30–33|终端用文字与程序交互。当前目录决定相对路径从哪里开始；普通权限足够完成大多数练习。看清命令、路径和作用后再运行，避免把管理权限当成解决所有报错的方法。|你在 notes 目录运行列出文件的命令，看到的是笔记目录，不是桌面的全部文件。切换目录后，同一个相对文件名可能指向不同文件。|命令里文件名相同，无论当前目录在哪里都会操作同一个文件。|在自己的练习目录查看当前位置与文件列表，记录绝对路径和相对路径的区别。|终端,当前目录,相对路径,权限|查看当前位置>切换练习目录>运行只读命令>核对输出
Git 与版本控制|33–36|Git 保存项目的版本历史。工作区是正在编辑的文件，暂存区选择本次提交内容，commit 形成本地记录，push 才把提交传到远程。clone 获取仓库，pull 获取并整合远程更新。|把页面标题从“笔记”改为“我的笔记”，先看差异，再只暂存这个文件并提交。远程页面要在 push 后才能看到新提交。|commit 成功，就说明远程仓库已经同步更新。|在练习仓库修改一行文字，查看差异并创建本地提交；解释暂存区为什么有用。|工作区,暂存区,commit,push,clone,pull|修改文件>检查并暂存差异>创建本地提交>推送到自己的远程仓库
Node.js 与 npm|36–39|Node.js 让 JavaScript 在浏览器之外运行。npm 管理软件包和项目脚本；package.json 描述依赖与命令，锁文件记录具体版本。安装运行环境与安装某个项目的依赖是两件事。|一个前端项目需要构建工具。先确认 node 与 npm 可用，再在包含 package.json 的目录安装依赖，最后启动开发脚本。|电脑装好了 Node.js，任何项目都不需要再安装依赖。|检查 Node.js 与 npm 的版本，并在一个项目中找到 scripts 和 dependencies 字段。|运行时,npm,依赖,package.json,锁文件|验证运行环境>进入项目目录>安装项目依赖>启动项目脚本
Markdown 文件|39–43|Markdown 用普通文本符号表达结构：井号表示标题，连字符表示列表，反引号标记代码，方括号与括号组合表示链接。它仍是文本，预览工具负责把符号显示成排版。|写一份日报，包含二级标题、三个待办项和一个代码块。换一个编辑器仍能读到原始文字，预览样式可能不同。|Markdown 必须使用某一个特定编辑器才能阅读。|写一份学习笔记，包含标题、列表、引用、链接、表格和代码块，并比较源码与预览。|标题,列表,代码块,链接,表格|编写纯文本结构>保存为 md 文件>打开预览>检查排版与链接
VSCode|43–46|编辑器帮助管理项目文件、搜索文本、预览文档和运行终端。打开文件夹能建立项目上下文；扩展添加语言或预览能力。保存文件后，磁盘上的内容才与本次编辑一致。|你修改一份日报却没有保存，外部预览仍显示旧内容。保存后重新加载，才看到新标题。|编辑器里看到的修改一定已经写入磁盘。|打开练习文件夹，新建一份 Markdown 笔记，保存后在文件管理器中确认文件位置。|编辑器,扩展,资源管理器,保存|打开项目文件夹>创建并编辑文件>保存到磁盘>打开预览验证
Codex|46–51|Codex 属于编程智能体工具，可围绕项目文件完成解释、修改和验证。产品入口、认证方法与模型支持会更新，应查看官方文档。第三方适配器与模型切换工具需要单独核查兼容性和来源。|给助手一个明确任务：给 ACME 的演示页面增加空输入提示。检查代码差异，再分别测试空输入与正常输入。|智能体报告“修复完成”，就可以省略运行和验证。|为一个按钮写出正常输入与空输入两种验收场景，让助手逐条说明如何验证。|编程智能体,项目上下文,差异,验收|描述具体任务>检查建议与改动>运行功能验证>记录结果
其他智能体|51–54|智能体有命令行、编辑器集成和常驻助手等形态。选择时比较工具权限、运行位置、数据处理、任务持续性和成本，而不是只看名称或排行榜。原文列举的不同产品用于说明这些形态。|只需改项目代码时，编辑器集成可能方便；需要定时整理文件时，需要能被可靠调度、记录执行状态的系统。|功能更多的助手在所有任务上都更适合初学者。|给“改网页”和“每天整理日志”分别列出三项必需能力，再选择合适工具形态。|命令行,编辑器集成,常驻助手,成本|写出任务需求>比较工具能力>在小样例中试用>按验证结果选择
第一次让智能体交付文件|视频补充|开始练习时先建立一个空文件夹，把它选为工作区，再提出一个能立刻验收的小任务。对话里出现“完成”只是报告；实际文件、内容和保存位置才是结果。|要求在练习目录创建 welcome.txt，内容为两行学习计划；随后用文件管理器打开，核对文件名、两行内容和目录。|第一次使用智能体就应该让它整理整个系统盘。|创建一份两行学习计划，并在笔记中记录完整路径与验收结果。|工作区,交付物,验收,访问范围|建立空练习目录>选定工作区与权限>提出最小文件任务>打开文件核对结果
Kimi Work 与多模态工具|视频补充|桌面智能体可以把模型、文件工具和媒体插件连接起来。模型能理解图片，不代表它自身能生成视频；生成图像、音频和视频可能使用不同服务，并有独立额度和等待时间。|先生成一张原创纸船插图，再以它为参考生成一小段动画。检查纸船颜色与形状是否保持一致，并记录用了哪些工具。|对话模型名称相同，就能证明图片、声音与视频都由同一个模型生成。|为一个媒体小项目列出输入、输出、调用工具和最多尝试次数，不必购买服务。|多模态输入,生成工具,插件,额度|核对当前产品能力>选择单一输出任务>记录工具与费用边界>检查媒体文件
WorkBuddy 的专家、技能与连接器|视频补充|专家提供面向领域的指导，技能规定可复用流程，连接器让应用访问被授权的外部服务。三者作用不同，也都需要实际结果验证。内置积分、自定义模型 API 余额与订阅额度需要分别核对。|用虚构数据整理一个项目表：专家帮助明确表格结构，技能规定格式，连接器负责读取获准的来源；没有连接器时也可先用本地样本练习。|安装一个专家就会自动获得所有外部账号的数据访问权。|给“每周整理项目资料”分别写出专家、技能、连接器的职责和权限。|专家,技能,连接器,用量|拆分任务职责>核对授权与计费>用样本验证流程>检查交付与访问范围
本地 Harness 与服务启动|视频补充|本地网页工具通常由后台服务和浏览器界面组成。终端启动服务后，浏览器才能访问实际输出的本地地址。关掉后台进程或重启电脑后，旧书签不会自动重启服务。具体安装命令和环境版本以当前官方说明为准。|昨天可打开的本地工作台今天提示无法连接。先确认后台服务是否运行，再检查启动日志和端口，而不是反复更换 API Key。|把本地地址保存成书签，就能在服务关闭时继续运行工作台。|画出终端进程、本地端口与浏览器之间的关系，并写出两条排障步骤。|本地服务,端口,进程,日志|核对安装环境>启动后台服务>打开日志给出的地址>关闭重开后复测
桌面、终端与编辑器的选择|视频补充|桌面、命令行和编辑器集成是交互方式，不是能力排名。鼠标操作、快捷键、文件预览和人工编辑便利程度不同；工具权限、模型、运行环境和支持的文件格式也要单独比较。|同一个学习卡片任务，桌面工具便于选文件夹，终端便于重复命令，编辑器便于逐行修改；用相同输入比较产物与操作成本。|终端界面看起来更专业，所以任何任务都一定做得更好。|用同一份虚构材料比较两种工具形态，记录结果、耗时和自己能否修改成品。|桌面,命令行,编辑器,操作成本|选定共同任务>保持输入与标准一致>比较实际产物>选择适合的交互方式
# 3|智能体实践|把零散操作连接成能检查、能复用的工作流程。
给 AI 搭建工作环境|54–55|工作环境包括清晰的目录、可读的资料、必要工具与版本记录。把输入、过程文件和输出分开，能让你定位错误；明确权限范围能防止助手把整个电脑当成练习空间。|为周报建立 input、work、output 三个目录。原始日志放 input，生成草稿放 output，修改前在 Git 中留下记录。|给助手越大的访问权限，产物就一定越准确。|设计自己的练习目录，并写下允许读写的位置和最终交付文件名。|目录,输入,输出,版本记录|整理输入资料>限定工作范围>验证所需工具>保存初始版本
与智能体的对话技巧|55–58|把需求说成可交付的动作，并给出完成标准。复杂任务先对齐步骤，执行中用真实结果纠正。把重复流程沉淀为说明文件，比每轮重新解释更稳定。|要求整理五条笔记时，明确输出表格的标题、主题和待核实项。收到草稿后指出哪一行遗漏，而不是只说“再好一点”。|反馈越模糊，智能体越容易猜出你真正的想法。|把“做个漂亮报告”改写为包含受众、输入范围、章节和验收标准的任务。|交付物,反馈,计划,验收|说明目标与输入>对齐工作步骤>检查中间结果>给出具体修正
Agent Skills|58–62|Skill 把某类任务的适用条件、操作步骤、参考资料或脚本放在一起，供助手按需使用。名称与描述帮助匹配任务，正文说明流程，引用资料提供细节。Skill 不会自动增加不存在的工具权限。|把整理周报的方法写成技能：何时使用、读取哪些日志、如何汇总、输出哪几个小节、怎样检查遗漏。|只要安装 Skill，助手就一定拥有访问任意网站的权限。|写一份整理学习笔记的技能草稿，包含触发条件、三步流程和验收清单。|Skill,元数据,工作流程,references|确定适用任务>写出可复用步骤>加入参考资料>用样例检查效果
第三方 Skill|62–65|第三方技能是别人提供的流程或脚本，安装前要阅读内容、检查来源、依赖和权限。热门不等于可靠。先用无敏感信息的样例测试，再决定是否用于真实工作。|一个表格技能附带上传脚本。你发现它会把输入发往外部服务，因此先确认数据流向，使用虚构数据测试输出。|收藏数量最多的技能可以不看内容直接运行。|阅读一个技能说明，列出它读取什么、写入什么、是否联网以及如何撤回安装。|来源,权限,依赖,数据流向|检查来源与文件>核对权限和依赖>用虚构数据测试>评估后再使用

Human-in-the-loop|221–225|Human-in-the-loop 在关键步骤让人确认或修正。可靠的审批要由执行代码暂停与校验，提示词只能辅助表达规则。审批应绑定具体操作和参数，修改操作后需要重新评估。|助手生成公开发布的课程草稿，先展示具体内容与目标位置；用户确认后，程序才允许发布该版本。|只在提示词里写“必须确认”，就能保证程序永远不越过审批。|为删除学习笔记设计审批信息：删除对象、影响范围、可恢复方式和确认后的动作。|审批,暂停,恢复,权限,审计|准备具体操作>展示影响与参数>等待有效确认>执行并记录结果
多智能体协作|225–227|多个智能体可分工处理写作、核查和整合，但会增加协调成本。共享消息要区分事实、建议与指令，最终负责人需要核对冲突，不能用多数意见替代证据。|一个助手起草学习总结，另一个检查来源，最后由协调者整理被证据支持的内容；两者意见冲突时回看原资料。|更多智能体参与，就一定比单个智能体更准确且更便宜。|把制作学习卡片拆成起草、核查、整合三个角色，给每个角色定义输入与输出。|分工,共享消息,协调,冲突,证据|明确角色与接口>分配可独立任务>共享可核实结果>处理冲突并整合
打造自己的 AI 学习助手|228–231|学习助手把文档检索、解释、笔记保存和记忆结合起来。先做只读问答，再增加结构化笔记与受控写入；评估应包括答不出来、资料冲突和工具失败等情况。|用户问一个课程问题，助手检索资料、给出解释和来源，再生成笔记草稿。保存前确认位置，保存后核对文件内容。|只测试一个成功问题，就足以证明学习助手已经可靠。|设计三个验收问题：资料中有答案、资料中没有答案、保存工具失败；写出期望行为。|学习助手,检索,笔记,记忆,验收|实现只读问答>加入来源与结构化笔记>增加受控保存>测试正常与失败路径
# 8|AI 底层原理|用直观示意理解生成模型的关键部件。
大模型训练流程|232–236|训练先准备与清洗数据，再选择架构，通过预测误差更新参数。预训练学习广泛模式，监督微调学习任务形式，偏好优化等后训练方法调整行为；独立评估检查泛化与风险。|把练习题用于训练，把未见过的题用于考试。若把考试答案混进训练材料，高分不能代表真正的泛化能力。|只要训练集成绩高，就证明模型在所有新问题上表现可靠。|画出数据准备、预训练、后训练、评估的流程，并说明为何要保留独立测试集。|预训练,微调,后训练,评估,泛化|准备与划分数据>训练基础模型>调整任务与偏好行为>在独立样本上评估
Transformer 架构概述|236–240|Transformer 用嵌入、位置表示、注意力与前馈网络处理序列，残差与归一化帮助稳定计算。常见自回归语言模型使用解码器结构，语言建模头输出词表上的分数或概率。|一句话先变为 Token 编号，再转成向量，经过多层处理，最后预测下一个 Token；不是把原文直接放进一个固定回答表。|所有 Transformer 都必然包含同样的编码器和解码器组合。|画出 Token、嵌入、计算层与输出头四个模块，标明每一步处理的对象。|Transformer,位置表示,前馈网络,解码器,输出头|把文本转成 Token>加入嵌入与位置信息>通过注意力和前馈层>计算下一 Token 分布
分词与嵌入|240–246|分词器把文字切成词表中的单位，可以基于字、词或子词。嵌入把编号映射为数值向量，模型学习这些向量用于后续计算。相似度取决于训练与使用场景，不是人工给每个词固定含义坐标。|“学习者”可能被切成一个或多个 Token，具体看分词器；嵌入表再为各编号取出向量，后续层结合上下文更新表示。|一个汉字在所有模型中都恰好对应一个 Token。|手动提出两种分词方案，说明为何它们只是示意，再用表格画编号到向量的映射。|分词器,词表,子词,嵌入,向量|选择分词规则>得到 Token 编号>查找嵌入向量>结合上下文处理
注意力机制|246–250|注意力让当前位置按相关程度汇总其他位置的信息。查询 Q 与键 K 计算匹配分数，归一化后加权汇总值 V。多头可学习不同关系；自回归生成还需要屏蔽未来位置。|“种子放进花盆，因为它需要土壤”中，模型需要结合上下文判断“它”指什么。注意力是计算关系的一种机制，不等于人类有意识地关注。|注意力权重可以直接证明模型拥有与人相同的理解过程。|给一句含代词的话画关联箭头，说明当前词可能需要参考哪些前文。|Q,K,V,权重,多头,因果遮罩|计算查询与键的匹配>应用必要的遮罩>归一化权重>加权汇总值向量
残差连接与层归一化|250–254|残差把输入与子层输出相加，为信息和梯度提供更直接的路径。层归一化通常在单个样本的特征维度上调整数值尺度，并有可学习参数；它不是把所有数据变成相同值。|把一层看成“原笔记加修改建议”，保留原信息的路径是残差的直观类比。归一化类似调整标尺，帮助后续处理更稳定。|层归一化会把每个特征都强制变成同一个数。|画一个输入分为两路再相加的图，并标出子层与残差；再说明归一化为何不是删除差异。|残差,梯度,层归一化,特征维度|保留输入路径>计算子层变换>合并信息>按架构安排归一化
自回归生成|254–257|自回归生成把已生成的 Token 作为下一步上下文，逐步输出序列。概率分布可以按贪心或采样策略选择，温度等设置影响随机性。生成遇到结束条件或长度上限停止。|相同开头可能生成不同故事，因为选择策略与随机采样不同。早期选词会改变后续上下文，影响整段走向。|语言模型每次都必须选概率最大的 Token，绝不可能采样。|手写一个有两个候选词的续写树，选择不同分支并观察后续句子如何变化。|自回归,概率分布,采样,温度,停止条件|读取已有上下文>计算下一 Token 概率>按策略选择>追加并检查是否结束
MoE 混合专家模型|257–262|MoE 在部分网络层设置多个专家子网络，由路由器为 Token 选择部分专家参与计算。总参数和激活参数不同，可以降低每次计算量，但仍有存储、通信和负载均衡成本。|像一个分诊台把不同问题交给部分科室，每次不需所有科室一起工作；但全部科室仍要部署和维护。|只激活少量专家，就意味着其他专家不占任何存储资源。|画出一个路由器与四个专家，让一个 Token 只走两条路径，区分总量和激活量。|MoE,专家,路由器,激活参数,负载均衡|接收 Token 表示>路由选择部分专家>执行专家计算>合并结果
智能体原理|262–268|智能体循环区分模型产生的决策与外部工具的观察。模型提出行动和参数，执行器执行，观察重新进入上下文。可靠实现需要预算、超时和终止判断，不能无限循环等待模型自己停下。|助手统计笔记时第一次读错路径，工具返回文件不存在；助手根据真实错误改正路径，成功后汇总，而不是编造读取结果。|Observation 是模型自行编写的一段想象结果，不需要来自工具。|模拟一次读文件失败再恢复的循环，写出两次行动与对应观察。|Thought,Action,Action Input,Observation,预算|提出行动与参数>执行工具>读取真实观察>决定重试或结束
# 9|多模态原理|理解图像、视频和声音如何进入 AI 的工作流程。
多模态概览|269–272|模态是信息形式，如文字、图像、声音和视频。理解任务把输入转成描述或判断，生成任务产生新内容；一个模型支持一种输入，并不代表能生成同种输出。|图表解读属于理解，按描述画一张图属于生成。选工具时分别确认输入类型与输出类型，不只看“多模态”标签。|能识别图片的模型，一定也能生成图片和视频。|把图片描述、文字配音、视频摘要、音乐生成四个任务按输入输出分类。|模态,理解,生成,输入,输出|明确输入形式>确定需要的输出>检查模型能力>核对生成或理解结果
